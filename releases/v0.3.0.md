Continuous sync, and a much faster `push`. ([#12](https://github.com/luutuankiet/looker-sync/issues/12))

- New command: `looker-sync watch [--validate] [--verbose] [--poll MS] [--force]`. It writes
  each save to your dev workspace and prints one line per event: `ack` when Looker accepts the
  write, then `verified` or `MISMATCH` after a read-back. A `.lkml` file that does not parse
  holds every pending file until it is fixed; one-shot `push` runs no such check and is the way
  past it. A file changed in Looker is held, never overwritten, unless you pass `--force` (see
  `docs/adr/0004-*.md`). `watch` never deletes, and it pauses rather than exits on a branch
  change or a refused session.
- `push` is faster. It reads from Looker only the files it will write or delete, reuses parallel
  keep-alive connections, and runs `git fetch` only when Looker's commit is not already known on
  the remote. New flags: `--no-validate`, and `--verbose` for step timings. Info-severity
  validation lines are now hidden and counted unless you pass `--verbose`.
- Behaviour change: a file changed only in Looker no longer refuses a `push` that leaves it
  alone. `status` and `pull` still report it. A file changed on both sides still refuses.
- `pull` now refuses (exit 2) when Looker has paths that differ only by case. A FIFO or a
  dangling symlink named like LookML no longer hangs or crashes a scan.
- Still no runtime dependencies. The syntax check uses a vendored copy of the MIT-licensed
  `lkml` parser.

Measured on Linux against a sandbox project:

| what | result |
|---|---|
| save to `ack`, atomic save | median 826.5 ms, p95 894.6 ms, n=20 |
| save to `ack`, in-place save | median 816.6 ms, p95 892.9 ms, n=20 |
| save to `verified`, atomic save | median 1215.4 ms |
| save to `verified`, in-place save | median 1177.4 ms |
| `push` with no change | median 2.961 s, n=5 |
| `push` with one change | median 5.320 s, n=5 |
| idle `watch`, 600 s, 50 ms poll | 4.81% of one core |

After the idle window a save acked in 865.0 ms and verified in 1229.1 ms.

The two `push` rows ran from a scratch copy of the test clone, because one unrelated file there
made `push` refuse in the clone itself. Each of those runs still wrote to and read from the real
sandbox.

Limits, stated plainly:

- This build of `watch` and `push` was not run on a Mac. An earlier prototype lost saves there
  under a burst of atomic renames; the rewrite has tests for that case, but they ran on Linux
  only. Case-only renames on a case-insensitive disk are also untested on a Mac.
- A real branch switch in the Looker IDE was not tested live. That row was measured by changing
  the name the watcher expects; Looker's branch never moved. Tests against a fake Looker cover
  Looker's own branch changing.
- The idle CPU figure is a thin margin under a 5% target, from one host.
- A real token expiry and refresh were not seen live: the longest live run was 600 s and a token
  lasts about an hour. Refresh and the retry on HTTP 401 are covered against the fake Looker.

Upgrade with `uvx looker-sync@latest`.
