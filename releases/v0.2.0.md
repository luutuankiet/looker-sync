Git-aware folders: when the folder is a clone of the Looker project's repository, `switch`
moves Looker and your local git checkout together, and the other commands refuse to sync one
branch's files onto another branch's checkout.

- `looker-sync link [--remote NAME]` links a folder to a git remote (default `origin`). `init`
  offers the link in a git clone; `--git-remote NAME` and `--no-git` choose without a prompt.
  A folder that is not linked behaves exactly as before and never starts a git process.
- In a linked folder every command first fetches and checks that Looker's commit exists in
  your clone. A clone of another repository is refused, with both remote URLs printed.
- `switch` in a linked folder checks out the branch in Looker, stashes uncommitted local
  work (`git stash push`, named `looker-sync <branch> <time>`), checks out the same branch in
  git (creating it from the remote if needed), fast-forwards it when it is behind Looker,
  then mirrors Looker's files. It prints how to get the stash back and never pops it.
  `--force` means: back up local changes and do not ask.
- If git is on a different branch than the folder syncs (or on a detached HEAD), `status`
  warns and `pull` and `push` refuse with exit 2, printing the `switch ... --force` line
  that fixes it.
- `push` refuses a branch Looker reports as read-only for you, such as a colleague's
  personal branch.
- Local git use is limited to reads, fetch, `stash push`, `checkout` and fast-forward-only
  merges, all through one checked runner. looker-sync never commits, pushes, pulls, resets,
  rebases, cleans or pops a stash. See `docs/adr/` for the decision record.

Upgrade with `uvx looker-sync@latest`.
