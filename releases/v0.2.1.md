Two fixes for git-aware folders.

- The commit check now proves the commit came from the linked remote. Before, it only proved
  that Looker's commit existed somewhere in your clone, so a clone with two remotes, linked
  to the one that lacks Looker's commit, passed. Now the commit must also be on a branch of
  the linked remote (`refs/remotes/<remote>/`) after the fetch. Otherwise every command
  refuses with exit 2, saying the commit "is in this clone but on no branch of remote", and
  prints both remote URLs. A failed fetch still only warns, and so does a Looker branch with
  commits it has not pushed yet. Local git use gains one read, `git for-each-ref --contains`
  (see `docs/adr/0003-*.md`). (#9)
- `switch` fast-forwards your local git branch on the first checkout of a branch that was
  only on the remote. Right after that checkout Looker reports an empty commit for the
  branch, which `switch` read as "nothing to do", leaving the local branch behind Looker. It
  now falls back to the remote's commit.

Upgrade with `uvx looker-sync@latest`.
